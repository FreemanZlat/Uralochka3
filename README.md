# Uralochka 3

A UCI-compatible chess engine using Alpha-Beta search and an NNUE-like neural network.

The engine implements:
- Main time controls (search to depth, time per move, time per game, including increment, time for N moves).
- Syzygy endgame tablebase support.
- Multithreading.
- Builds for different CPU extensions (SSE, AVX2, AVX512) and operating systems (Windows, Linux).

Briefly about the architecture (overall, it is typical for engines of this level) and the technologies used:
- Position representation and move generation - magic bitboards.
- Move ordering: move from transposition table, good captures by SEE, killer moves, quiet moves by history, bad captures by SEE.
- Search - PVS, Aspiration search, Quiescence Search. And all possible search reductions and prunings (Null move, Static null move, quiet move reductions, Futility pruning, SEE pruning, LMR for quiet moves).
- Transposition table for move ordering and pruning of already explored positions, also for caching evaluation.
- Multithreading - Lazy SMP.
- Evaluation - NNUE-like neural network. Network architecture: (2 x (12288 x (1280 + psqt x 6)) -> crelu -> pairwise multiplication + concat: 1280 -> (6 -> screlu -> 32 -> relu -> 1 + psqt) x 6. Input layer: KingArea*Piece*Color*PieceSquare 16*6*2*64.
- Inference implemented in the engine using the accumulator principle and vector instructions (SSE, AVX).
- Handwritten evaluation function (currently unused) - material, PSQT, king’s pawn shield, king attacks, pawn structure, piece mobility. Weights tuned using Texel’s tuning method.
- Neural network training utility using the PyTorch framework.
- Dataset of 28 billion positions generated by previous versions of Uralochka in games with 10-12 ply control. The dataset also includes positions from Uralochka’s games against some other engines, evaluated by Uralochka.

External libraries used in the engine:
- https://github.com/official-stockfish/nnue-pytorch/blob/master/feature_transformer.py - class implementing fast sparse tensors for PyTorch from the nnue-pytorch project. Provided noticeable training speedup.
- https://github.com/jdart1/Fathom - access to Syzygy endgame tablebases.
- https://github.com/graphitemaster/incbin - embedding binary files into the executable.
- https://github.com/rogersce/cnpy - saving datasets in NumPy format.
- https://pstreams.sourceforge.net - launching processes in Linux.

Engine history:
- I started getting into chess programming around 2006, wrote the engine FreeChess, which was quite weak.
- After participating in the CIS Championship in 2008 and communicating with the authors of the best CIS engines, I started a new engine, Uralochka (name suggested by Igor Korshunov, author of WildCat). It played much stronger than FreeChess but was still relatively weak (about 2200 CCRL rating).
- Around 2014 I made an unsuccessful attempt to write a new engine - Uralochka 2. By my estimates, its rating was around 2400 CCRL, but at some point, the laptop’s hard drive died and the sources and binaries were lost. Unfortunately, nothing has been preserved for history.
- In spring 2021, colleagues at work decided to compete in writing a chess engine. I decided to join and started a new, 3rd version of Uralochka. Since I was constrained by the deadline of our "contest", I wrote everything in a hurry, used an 0x88 move generator, and made the search and evaluation similar to the first Uralochka. Since I was the only one who had a working engine, the contest did not take place. I decided to continue developing Uralochka (at least as long as there is noticeable progress). Gradually I rewrote the generator to magic bitboards (but not fully - pawn moves are still generated via coordinates, not bitboards, too lazy to fix properly), implemented main reductions/prunings in search, made evaluation more complex, implemented tuning with Texel’s method. By spring 2022, progress slowed significantly (around 3100 CCRL), and I decided to move towards neural networks. After a couple of months of experiments, I got the first version with a neural network instead of the evaluation function, which was stronger than the version with handwritten evaluation. After several training cycles (training on data generated by the previous version) and some neural network improvements, I released the engine publicly.
